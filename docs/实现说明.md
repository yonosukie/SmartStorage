# 本地开发版实现说明

## 本轮约定

根据用户确认：先完成本地功能，AI 与云备份预留接口，后续接入。`RecognitionService` 和 `CloudBackupService` 位于 core 模块；名称/分类识别仍未接入。v0.3.0 新增可选 remove.bg 抠图，因此声明 INTERNET 权限；用户配置并开启后才上传照片，详见功能增强说明。

## 数据与安全

- Room 保存关系实体；余额与流水在同一个数据库事务提交，应用通过 Mutex 串行化更新。
- 核心规则执行完整关联校验；数量不为负，移动保持同批次，操作 ID 防止重复执行。
- 撤销依赖受影响余额的 revision。后续有操作时拒绝覆盖旧状态，用户可用盘点调整。
- 图片导入后缩小，透明图片保留 PNG，其余使用 JPEG，保存在应用私有目录。可选 remove.bg 抠图输出透明 PNG。
- 备份使用自定义 `.ssb` 容器：格式头、可选加密层、ZIP 中的版本化 JSON、照片和 SHA-256 校验清单。
- 密码备份使用 PBKDF2-HMAC-SHA256（210000 次）与 AES-256-GCM，随机 salt/IV。错误密码或认证失败不会进入恢复流程。
- 恢复校验版本、关联与路径；新照片写入全新文件名，数据库事务失败时删除新文件，不改写旧图。恢复前保留一份本地安全快照，可从设置页导出。
- 当前备份编解码限制为 128 MB 解压内容，使用有界内存处理；较大资料库需后续流式实现和设备内存测试。
- Excel 以 OOXML 写出，用户字符串始终是文本单元格，避免被视作公式。

## 相比完整设计的首版简化

以下应在后续迭代补齐，不视为已完成的设计验收项：

1. 分类使用可自定义的平铺名称，尚未实现分类树、分类多选和独立分类管理页；标签和空间支持多层/组合语义。
2. v0.2.0 空间与物品改为自适应卡片网格，容器支持按层管理。尚无列表/网格切换或批量选择移动。支持单批次部分移动与跨空间位置选择器。
3. 拍照调用系统相机；尚无内嵌 CameraX 裁剪页、多图相册管理或持久化表单草稿。表单离开时提示放弃。
4. 房间布局为固定方形相对坐标画布，支持容器尺寸、90 度旋转及网格吸附；尚无自定义房间轮廓、画布平移缩放、布局上物品拖放；点击容器后可进入分层管理。
5. 行李箱模板是独立检查清单，暂不关联真实物品，也不自动移动库存。
6. 通知采用每日聚合、全局/批次临期窗口与批次暂停；不是多个提前日期分别派发的提醒日程。
7. 备份为手动导出/恢复，尚未提供进度百分比和中途取消。历史安全快照保留一份。孤立图片定期清理尚未启用。
8. 设置当前使用数据库元数据保存；尚未改用 DataStore。v0.2.0 日期已使用 Material 3 日历选择器，单选使用单选对话框。
9. 首版筛选/统计基于内存快照，无分页查询优化；大数据性能目标尚未验收。
10. 首页和统计的贵重物品按手动标记筛选，不提供价格阈值建议。

## 验证入口

- `:core:test`：库存、日期、筛选、标签、备份与 Excel 规则。
- `:app:testDebugUnitTest`：Robolectric 下验证 Room 外键与事务行为。
- `:app:lintDebug`：Android 静态检查。
- `:app:assembleDebug`：完整资源和代码编译、调试 APK 打包。

真机验收重点：相机提供器返回、照片方向、系统文件选择器、恢复后的重启读取、通知授权/省电策略、长按拖拽与大字体布局。最终执行结果由交付记录另行列出，以上入口本身不代表已运行通过。
