# SmartStorage Android App 设计文档

版本：v0.1 ｜ 日期：2026-09-22 ｜ 状态：开发前方案

## 1. 产品目标与设计范围

帮助个人和家庭回答四个问题：物品在哪里、还剩多少、什么时候到期、已经拥有多少。

本文件是 Android 首版产品与技术设计，覆盖全部十项需求，可作为页面设计、数据库建模和开发拆分的依据。本阶段不包含 App 代码实现。

### 1.1 默认产品决策

- 首版面向单人管理，支持多个房子；家庭成员协作和多设备实时同步不进入首版。
- 本地数据为主，无需注册即可完成手动录入、空间管理、搜索、库存、布局和统计。
- AI 识别、云备份均为可选联网能力；拒绝相关授权不影响基础功能。
- 使用简体中文；默认人民币。首版每个资料库使用一种币种，不混合不同币种计算价值。
- 支持整数数量和可配置计量单位，例如件、瓶、袋、盒；按毫升、克等小数扣减留作后续扩展。
- 允许物品暂不归入空间，进入“待归位”；位置、购买日期、价格、有效期均可后补。
- 核心数据归属个人资料库；切换房子只改变浏览范围，不另建数据库。

### 1.2 设计原则

1. 快速录入：先记录名称和数量，再逐步补充信息。
2. 自动结果可确认：AI 结果只作建议，保存前可编辑。
3. 数量变化可追溯：消耗、补货、调整和过期处理均保留记录。
4. 本地操作即时生效：网络失败不阻塞离线管理。
5. 结构化位置为唯一依据：列表和房间布局引用同一份位置数据。

## 3. 信息架构与页面设计

底部导航采用“首页 / 空间 / 物品 / 我的”；首页和物品页提供醒目的“＋录入”按钮。统计、收纳方案从首页进入，备份和设置位于“我的”。

```text
首页
├─ 全局搜索入口、当前房子范围
├─ 临期 / 已过期 / 待归位数量
├─ 即将过期列表 → 批次详情 → 消耗 / 丢弃 / 修改日期
├─ 最近添加物品
└─ 统计、收纳方案快捷入口

空间
├─ 房子列表 → 房间列表 → 容器列表 → 容器内物品
├─ 房间：列表 / 布局切换
└─ 新建、编辑、排序、归档、移动

物品
├─ 搜索框、筛选面板、排序、列表 / 网格切换
├─ 物品详情 → 库存批次、位置分布、流水
└─ 录入：拍照 / 相册 / 手动

我的
├─ 分类与标签管理
├─ 备份与恢复、Excel 导出
├─ 提醒设置、币种与显示设置
└─ 可选云账号、隐私与数据管理
```

| 页面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 首页 | 总数量、临期批次、过期批次、待归位、最近添加 | 添加、搜索、处理提醒 |
| 录入页 | 照片、名称、分类、数量、单位、位置；展开后显示价格/日期/标签 | 识别、修改、保存并继续 |
| 物品列表 | 图片、名称、剩余数量、位置摘要、最早到期时间 | 筛选、排序、批量移动、消耗 |
| 物品详情 | 基础资料、多个批次、各位置数量、价值、流水 | 编辑、补货、消耗、移动、归档 |
| 容器详情 | 完整位置路径、物品卡片、数量合计 | 添加、移入、移出、编辑容器 |
| 房间布局 | 房间边界、容器图形、名称、选中状态 | 拖拽、缩放、旋转、查看物品 |

### 3.2 视觉与交互规范

- 风格以清晰、轻量为主，浅色背景配绿色主色；临期使用橙色，过期使用红色，同时提供文字和图标，避免只靠颜色传达状态。
- 常用操作保持单手可达；物品卡片优先展示名称、数量、位置和到期状态。
- 长按进入拖拽，普通点击进入详情；“移动到”菜单是拖拽的等价替代，便于无障碍操作。
- 表单校验定位到具体字段；未保存退出时保留草稿或提示放弃。
- 空列表提供明确行动，例如“拍照记录第一件物品”；加载、空结果、失败和离线分别展示。
- 支持系统字体缩放、深色主题和读屏标签；触控目标按 Android 无障碍规范实现。

## 4. 详细功能与业务规则

### 4.1 物品录入与 AI 识别

流程：拍照/选择照片 → 图片预览与裁剪 → 同意上传用于识别 → 返回候选 → 编辑确认 → 保存本地。

- AI 输出名称、分类候选、可选品牌及置信状态；用户可以接受或改写。
- 一张照片含多件物品时展示候选列表，用户逐项选择并确认；不得直接批量入库。
- 不根据外观自动确定数量、价格或保质期。即使后续支持日期文字识别，也必须由用户确认。
- 识别失败、超时、断网时保留照片和已填字段，提供“重试”和“改为手动录入”。
- 必填字段仅为名称、数量、单位；分类默认“未分类”，位置默认“待归位”，初始数量至少为 1。
- 支持同名提示，但不自动合并；用户可选择“作为现有物品补货”或“新建物品”。
- 保存通过单次事务创建物品、批次、位置库存和入库流水；重复点击不会重复创建。
- 本地图片使用应用私有存储，数据库保存相对路径；展示使用缩略图。

字段建议：名称、照片、分类、标签、备注、贵重标记；批次记录数量、单位成本、购买日期、到期日和存放位置。

### 4.2 空间架构与移动

结构为“房子 → 房间 → 收纳容器”，支持房间直接存放物品。衣柜、抽屉、收纳箱、柜子是容器类型；P2 可启用容器内子分区，例如“主卧 / 衣柜 / 上层抽屉”，容器嵌套最多三层。

- 新建房间可选客厅、卧室、厨房、卫生间、书房、储物间或自定义类型。
- 同级位置名称不可重复；改名不影响物品关联。
- 拖拽物品到同屏容器卡片后，高亮目标并显示路径；批次可移动全部或指定数量。
- 跨房间/房子移动、长距离移动使用“移动到”位置选择器；禁止无目标释放后改变位置。
- 移动保持批次的购买日期、到期日和价格不变，原位置扣减、目标位置增加，总量不变。
- 容器调整所属房间时，其全部子容器和物品随之改变位置路径；禁止循环父子关系。
- 删除非空空间前要求迁移内容，或显式选择将全部内容放入待归位；不得级联删除物品。
- 容器被移到另一个房间后，移除旧房间的布局映射，新房间显示“待布局”。
- 可归档空房子/房间/容器；归档对象不出现在普通位置选择器中。

### 4.3 全局搜索与筛选

搜索覆盖物品名称、品牌、备注、分类、标签和位置名称。全局搜索默认跨全部房子；进入空间页时默认限制当前空间，可清除范围。

| 筛选项 | 规则 |
| --- | --- |
| 分类 | 可多选，选择父分类包含子分类 |
| 位置 | 房子/房间/容器树选择，包含后代位置，支持待归位 |
| 标签 | 默认匹配任一所选标签，可切换为匹配全部 |
| 有效期 | 已过期、临期、未到期、未设置、自定义日期区间 |
| 价格 | 按批次单价区间筛选，边界包含；未设置价格单独选择 |
| 库存 | 默认仅在库，可切换包含零库存与已归档 |

- 不同筛选维度取交集，同一维度的多个选项默认取并集。
- 涉及位置、日期、价格的条件必须由同一条在库批次位置记录同时满足，避免不同批次拼出错误结果。
- 列表按物品去重，同时显示命中库存数量；详情可查看命中批次。
- 支持按最近添加、名称、最早到期日、当前总价值排序；缺失值排在末尾。
- 展示已选条件和结果数，提供一键清空；保留用户最近筛选状态。
- P1 中文搜索采用规范化后的子串匹配；后续数据规模增长时再引入适合中文的分词索引。排序字段采用白名单，查询参数绑定。

### 4.4 自定义标签

- 标签包含名称与颜色，例如“常用”“旅行”“备用”“需补货”“纪念品”。
- 一个物品可关联多个标签；去除前后空格后名称全局唯一。
- 支持创建、改名、改色、合并和删除；删除只解除关联，不删除物品。
- 分类表示物品的主要类型，标签表达跨分类属性；每个物品有一个主分类。

### 4.5 库存与批次

采用“物品档案 + 库存批次 + 位置库存”模型。同款牛奶可有两次购买、不同到期日，并分别放在厨房和冰箱，不应只记录一个总数量和一个有效期。

- 补货：创建新批次；用户明确确认所有批次信息一致时才可合并。
- 消耗一件：默认推荐最早到期的在库批次；无到期日的批次排后，再按购买日期和创建时间排序。可改选批次及位置。
- 数量增减：区分入库、消耗、丢弃、盘点调整，不把所有减量都记为消耗。
- 库存永不为负，减少量不得超过对应位置的可用量；快速重复点击通过事务和操作唯一 ID 防重。
- 已过期批次不会自动扣减；消耗过期物品需明确确认，也可选择丢弃处理。
- 库存为零后保留档案与流水，默认从在库列表隐藏，可再次补货。
- 撤销通过补偿流水完成；只有受影响记录自原操作后未被修改时才允许直接撤销，否则提示重新调整。
- 到期日、单价等批次资料修改不改变库存；保留修改时间，关键数量变更必须有流水。

示例：牛奶 A 批次 6 盒（10 月 1 日到期），B 批次 4 盒（10 月 15 日到期）；消耗一件后 A 为 5、B 为 4、总数为 9。把 A 的 2 盒移到另一房间后，总数仍为 9。

### 4.6 备份、恢复与 Excel 导出

#### 本地备份

- 数据库与图片均保存在本地；用户通过系统文件选择器导出独立备份包。
- 备份包包含格式版本、创建时间、资料库 ID、数据清单、图片和逐文件校验值。
- 必须生成一致性快照，不直接复制正在写入且存在未合并 WAL 的数据库文件。
- 本地备份可设置密码；加密采用成熟库实现的认证加密及密码派生方案，不自行设计算法。
- 恢复先校验完整性、格式版本、空间与密码，在临时目录验证数据库及引用，再原子替换正式数据。
- 恢复采用整库替换，显示快照时间与物品数，并先生成当前资料库的安全快照；首版不进行跨库合并。
- 恢复后重建搜索索引、缩略图及提醒任务；失败保留原资料库。

#### 可选云备份

- 用户主动启用并登录后，将加密快照上传云端；它是快照备份，不承诺多设备实时同步。
- 支持手动备份，以及按用户设置在合适网络和电量条件下自动备份；设置保留最近 N 份，默认 7 份。
- 服务端只接收加密快照与必要元数据；解密密码不上传。用户需在其他设备恢复时输入密码，忘记密码无法解密旧快照。
- 新快照上传并校验成功后才能清理超出保留数量的旧快照；失败可重试，不覆盖最近可用备份。
- 展示最后成功时间、失败原因和重试入口。停用备份与删除云端历史分别操作。

#### Excel 清单

- 导出 `.xlsx`，工作表包括“物品汇总”“批次与位置”“库存流水”“统计口径”。
- 物品汇总字段：物品 ID、名称、分类、标签、单位、当前数量、已知成本总额、缺价数量、贵重标记、位置摘要。
- 批次与位置字段：批次 ID、物品 ID、完整位置、数量、单价、购买日期、到期日、状态。
- 流水字段：操作时间、物品、批次、类型、数量、来源位置、目标位置、备注。
- 支持当前筛选结果或全部数据；导出时固定快照，避免多个工作表数据不一致。
- 名称和备注等用户输入按文本单元格写入，防止被 Excel 当作公式执行。默认不嵌入图片以控制体积。
- Excel 用于阅读分析，不作为完整恢复格式；备份包才包含所有数据及图片。

### 4.7 保质期预警

- 食品、化妆品、药品可以设置日期，其他分类同样支持；未填写日期不推断为长期有效。
- 到期日采用本地日历日期，默认含到期当天；例如 9 月 22 日到期，在 9 月 23 日才归类“已过期”。
- 全局默认临期窗口为 7 天，可设置为其他天数；批次可覆盖默认设置，并可设提前 30/7/1 天提醒。
- 首页展示仍有库存的临期与已过期批次，按到期日排序；零库存批次不提醒。
- 按日聚合通知，避免同一物品多个批次反复弹出；去重键包含批次、提醒日期和规则版本。
- 用户可暂停某批次提醒；修改日期或补充库存后重新计算。
- Android 系统可能延迟后台任务，产品承诺“按日提醒”，不承诺分钟级准时。打开 App 时同步刷新首页状态。
- 未授予通知权限时显示站内提醒，并在提醒设置中说明当前状态；修改日期、时区、重启及恢复备份后重新安排任务。

### 4.8 收纳方案库

首批内置模板：

| 模板 | 示例分区 / 内容 |
| --- | --- |
| 衣柜分区 | 挂衣区、叠衣区、内衣区、换季区 |
| 抽屉分格 | 文具、线材、小工具、证件 |
| 零食柜 | 饼干、坚果、饮品、临期优先区 |
| 化妆品收纳 | 日常护肤、彩妆、工具、囤货 |
| 行李箱打包 | 证件、衣物、洗漱、电子设备、药品 |

- 模板包含标题、说明、建议分区、建议标签和检查项，不自动产生真实库存。
- 应用向导：选择目标房间/容器 → 预览将创建的分区 → 重命名或取消部分分区 → 确认创建。
- 同名分区要求选择复用或重命名；重复应用不能静默创建重复内容。
- 行李箱模板创建独立打包清单，可关联真实物品；勾选“已装入”不扣减库存。
- 需要改变物品位置时，另行确认移动到指定行李箱容器；取消勾选也不会自动移动回来。
- 模板是建议，应用后允许自由编辑，不影响原始模板。

### 4.9 平面房间简易布局

- 使用二维画布表达相对位置，首版不提供建筑测绘、真实比例承诺或 3D 效果。
- 每个房间一个布局，支持矩形房间、网格、平移和缩放。
- 编辑模式可新增/关联柜子、收纳盒等容器，拖拽位置、调整尺寸、旋转、修改显示名称。
- 坐标保存为房间坐标系中的逻辑单位，屏幕缩放不修改模型坐标；可吸附网格，超出房间边界时限制放置。
- 浏览模式点击图形进入容器详情；嵌套抽屉在容器详情展开，避免房间画布拥挤。
- 允许图形重叠并可调层级；重叠时提供容器列表作为选择入口。
- 一个容器在所属房间最多对应一个图形；移除图形只取消布局显示，不删除容器或物品。
- 布局编辑支持撤销/重做、显式保存和放弃；业务数据更新导致容器失效时提示刷新。
- 在容器详情选择物品后，可进入布局目标选择模式，拖到目标图形完成库存移动；跨房间使用位置选择器。

### 4.10 物品统计

统计可按全部房子或选定房子查看，并支持房间、分类、标签维度下钻。

| 指标 | 计算口径 |
| --- | --- |
| 物品种类数 | 范围内当前数量大于 0 的物品档案数 |
| 库存数量 | 范围内数量合计，按单位分组；瓶、盒、件不合并成一个业务数量 |
| 当前库存价值 | 范围内各批次位置数量 × 该批次单价，汇总已填写价格部分 |
| 贵重物品 | 用户标记为贵重的在库物品及已知成本总额；价格阈值只作筛选建议 |
| 拥有时间 | 在库批次的今日日期减购买日期，按不足 30 天、30–179 天、180–364 天、365 天以上分组 |
| 过期库存 | 已过期且有库存的批次种类数、分单位数量、已知成本总额 |
| 历史过期损耗 | 标记“过期丢弃”的流水数量与当时成本快照之和 |

- 价格表示购入单价，当前库存价值不等于二手估值或累计消费金额。
- 未填价格不记为 0 元，汇总注明“已知价格部分”和缺价数量；购买日期未知则单列“未知”，不使用录入日期替代。
- 金额以最小货币单位整数存储，避免浮点误差。
- 按房间统计时只计算该房间实际存量；物品分散多个房间时价值按各位置数量分摊。
- 多标签统计可能重复覆盖同一物品，图表明确提示不可把各标签合计直接相加。
- 首页的简要数字与统计详情使用同一套查询规则。

## 5. 数据模型

所有业务实体使用 UUID；主要实体带创建/更新时间。关系通过外键约束，删除策略默认限制删除，涉及多表修改使用事务。

| 实体 | 关键字段 | 关系与约束 |
| --- | --- | --- |
| Location | id、parentId、type、name、containerType、sortOrder、archivedAt | type 为 HOUSE/ROOM/CONTAINER；校验父类型、深度与循环 |
| Item | id、name、brand、categoryId、unit、notes、valuable、archivedAt | 物品档案；总量从库存计算 |
| ItemPhoto | id、itemId、relativePath、sortOrder、checksum | 一物多图，首图为封面 |
| Category | id、parentId、name、sortOrder | 内置分类和自定义分类；深度限制 |
| Tag / ItemTag | id、name、color / itemId、tagId | 多对多，组合唯一 |
| StockBatch | id、itemId、purchaseDate、expiryDate、unitCostMinor、createdAt | 一个批次共享单位成本和日期 |
| StockBalance | id、batchId、locationId、quantity、revision | 同一批次同一位置唯一，数量非负 |
| StockOperation | id、type、occurredAt、reason、reversesOperationId | 一次用户操作对应唯一防重 ID |
| StockEntry | id、operationId、balanceId、delta、unitCostSnapshot | 移动为来源负项和目标正项；数量变化流水 |
| ReminderRule | id、batchId、leadDays、enabled、revision | 批次级覆盖，缺省使用全局配置 |
| ReminderDelivery | id、batchId、ruleRevision、scheduledDate、status | 通知去重与发送状态 |
| RoomLayout | id、roomId、width、height、revision | roomId 唯一 |
| LayoutNode | id、layoutId、containerId、x、y、width、height、rotation、zIndex | containerId 唯一，需属于该房间 |
| StorageTemplate | id、name、version、definitionJson | 内置模板使用带版本的资源定义 |
| PackingList / PackingEntry | id、name / listId、title、itemId、quantity、checked | 可选关联物品，不参与库存计算 |
| BackupRecord | id、createdAt、target、status、checksum、formatVersion | 本地/云备份执行记录 |

待归位采用不可删除的系统位置记录，避免可空位置导致唯一约束失效；该记录不属于任何房子。位置名称唯一性按规范化名称校验，根房子同样适用。

库存不在 Item 上额外存储总量，避免多份数量失去一致性。StockBalance 是当前库存，StockEntry 为审计流水；每次数量变化必须同时更新二者。

索引至少覆盖位置父节点、分类、标签关联、批次所属物品、到期日、位置库存、流水操作时间。可用闭包表或递归查询加速位置后代范围查询，依据设备数据量测试后确定。

### 5.1 核心事务示例：移动 2 件

1. 校验来源库存不少于 2，目标位置有效且未归档。
2. 检查操作 ID 未执行，并读取来源 revision。
3. 使用条件更新扣减来源 2 件，同时增加或创建目标库存。
4. 写入 MOVE 操作以及 -2 / +2 两条流水。
5. 提交事务并刷新列表、布局详情和统计；任一步失败则整笔回滚。

## 6. Android 技术方案

以下是拟采用的架构选择，不锁定具体依赖版本；进入开发时验证 Android SDK、库版本与兼容矩阵，并锁定可复现构建。

- 语言：Kotlin；UI：Jetpack Compose，采用 Material 设计组件。
- 架构：UI → ViewModel → 用例层 → Repository → Room/文件/网络，状态单向流动。
- 本地持久化：Room + SQLite；轻量设置使用 DataStore；数据库迁移提供版本化脚本。
- 异步：Coroutines + Flow；拍照、AI、导出、备份均不阻塞主线程。
- 拍照：CameraX；相册和导出通过系统选择器获取最小必要访问范围。
- 提醒与自动备份：WorkManager 承担可延迟后台工作；站内状态实时计算。
- 图片：成熟图片加载库，限制解码尺寸并缓存缩略图。
- 布局：Compose Canvas 或可组合图形层；手势坐标统一映射到房间坐标系。
- Excel：通过独立导出接口接入 Android 兼容的 XLSX 写入实现，优先流式写入；选型时验证内存占用和许可证。
- 最低系统版本暂定 Android 8.0（API 26）；目标 SDK 在开发与发布时按实际分发要求确定。

### 6.1 建议模块

```text
app                 导航、依赖装配、启动
core/model          领域模型与业务规则
core/database       Room、迁移、事务
core/data           Repository、文件与网络访问
core/ui             主题、卡片、表单、通用状态
feature/home        首页与提醒入口
feature/item        录入、详情、搜索、库存
feature/space       空间树、移动、房间布局
feature/template    模板与打包清单
feature/statistics  汇总、图表与明细
feature/settings    标签、备份、恢复、导出
```

可先按包组织，随规模增长拆成 Gradle 模块，不为首版引入过多构建复杂度。

### 6.2 AI 与云端边界

客户端通过自有轻量服务调用 AI，模型密钥不得放入 APK。服务端验证会话或受限匿名令牌、限制图片大小与调用频率，对模型结果执行结构校验。

建议契约：

| 接口 | 输入 / 输出 | 失败处理 |
| --- | --- | --- |
| POST /v1/recognitions | 图片、请求 ID → 候选名称、分类、置信状态 | 超时/限流显示可重试，保留本地草稿 |
| POST /v1/backups/upload-session | 快照大小、校验值 → 上传会话 | 可重试，尚未完成的快照不可恢复 |
| POST /v1/backups/{id}/complete | 上传完成校验 → 可用快照元数据 | 校验失败不标记成功 |
| GET /v1/backups | 当前账号快照列表 | 离线显示本地最后状态 |
| GET /v1/backups/{id}/download | 鉴权后的加密快照下载 | 下载后在本地再次校验 |
| DELETE /v1/backups/{id} | 删除指定云快照 | 用户主动操作，展示结果 |

AI 服务商、云存储服务商和计费额度留到实施时选定，通过接口隔离，不改变本地核心数据模型。上传图片前去除非必要元数据；服务端不默认长期保存识别图片。

## 7. 权限、隐私与异常状态

- 相机权限仅在拍照时申请，拒绝后仍支持相册和手动录入。
- 通知权限在用户启用提醒时申请，拒绝后保留首页预警。
- 图片只在用户启动 AI 识别时发送至识别服务，界面说明处理用途；本地手动录入不上传图片。
- 云账号仅用于云功能；备份按账号隔离，鉴权失败不读取其他账号数据。
- 日志不记录图片内容、解密密码、访问令牌或完整个人备注。
- 默认排除未加密数据库和图片被系统隐式云备份，防止与“可选云备份”的产品承诺冲突；实施时配置并验证系统备份规则。
- 本地备份导出前提示文件内容和保存位置；密码与令牌使用系统安全存储能力，备份包不包含云登录凭据。
- 磁盘不足时终止录入图片或备份，保留现有数据；空图片引用、丢失图片使用占位图并提供修复入口。
- 数据库损坏不自动覆盖原文件；提供恢复已有备份的入口。卸载会移除应用私有数据，备份页需明确说明。

## 8. 性能与质量目标

以下为验收目标，需在选定的基准设备上实际测量，不代表已达到。

- 基准数据：10,000 个物品档案、30,000 个批次、50,000 条位置库存和 100,000 条流水。
- 在 Android 10、4 GB 内存的基准设备上，常用搜索与筛选 P95 不超过 500 ms（不含输入防抖）。
- 本地单笔消耗和移动 P95 不超过 300 ms，列表通过分页加载。
- 冷启动到首页可交互目标不超过 2 秒；AI 与备份耗时单独显示状态，不纳入首页阻塞路径。
- 50 个布局图形下拖拽目标为稳定流畅，需通过帧耗时测试定位卡顿。
- 大规模导出/备份显示进度并可取消；中断后清理临时文件，不能留下被当成成功结果的半成品。
- 图片生命周期随引用管理：备份失败、取消录入和删除图片后的孤立文件由可恢复清理流程处理。

## 9. 验收场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 离线手动录入 | 新建、重启后查看成功，全部字段保留 |
| A02 | AI 失败与修改 | 失败可转手动；修改名称分类后按确认值保存 |
| A03 | 部分移动 | 6 件移动 2 件后来源 4、目标 2、总量不变 |
| A04 | 不同批次消耗 | 推荐最早到期批次，实际只扣指定批次及位置 |
| A05 | 快速重复操作 | 同一操作 ID 不重复扣减，不产生负库存 |
| A06 | 组合筛选 | 标签/位置/有效期/价格按约定逻辑匹配，同批次条件一致 |
| A07 | 删除标签/非空空间 | 标签不删除物品；非空空间必须先完成迁移 |
| A08 | 到期边界 | 到期当天未过期，翌日过期；零库存不提醒 |
| A09 | 通知不可用 | 拒绝权限及后台延迟不影响首页临期数据 |
| A10 | 备份恢复 | 重装后的测试环境恢复字段、图片、位置、布局与数量一致 |
| A11 | 错误备份包 | 密码错误、损坏、版本过高恢复失败且原库不变 |
| A12 | Excel 导出 | 中文、日期、金额正确；特殊名称为文本，汇总与明细一致 |
| A13 | 模板应用 | 仅创建分区/清单，不虚构库存；重复应用可处理同名 |
| A14 | 布局操作 | 重启与屏幕尺寸改变后相对位置一致；移除图形不删除物品 |
| A15 | 价值统计 | 多位置分摊正确，缺价单列，过期丢弃保留历史成本 |
| A16 | 云端中断 | 上传中断不影响本地使用，旧快照仍可恢复 |
| A17 | 撤销与并发修改 | 无后续变更可撤销，有后续变更则阻止旧操作直接覆盖 |
| A18 | 数据库升级 | 从各已发布版本迁移后数量、关系和图片引用保持一致 |

业务规则采用单元测试；数据库事务、迁移和恢复使用集成测试；拍照授权、拖拽、通知及系统后台行为在真实 Android 设备上验证。

## 10. 实施顺序与交付物

1. **基础设计与骨架**：页面线框、主题、导航、模型与数据库迁移基线；先打通离线启动。
2. **录入与空间闭环**：手动录入、图片、空间树、标签、批次、消耗和移动；交付可操作的内部 APK。
3. **搜索、预警与 AI**：完成组合筛选、提醒规则、首页和识别服务；验证失败降级路径。
4. **P1 数据保障**：统计基础、本地备份恢复、Excel 导出与迁移测试；交付可日常使用版本。
5. **P2 完整体验**：云备份、五类模板、房间布局与完整统计；覆盖全部十项需求。
6. **发布准备**：真机回归、性能测量、隐私说明、签名与发布配置；交付源码、安装包、测试记录和使用说明。

工期应在页面原型、AI/云服务接入方式和开发资源确定后估算，避免以未经验证的时间承诺替代工作拆分。
